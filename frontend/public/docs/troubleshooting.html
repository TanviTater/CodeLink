Troubleshooting Manual

A practical, evidence-first method

Close this guide ×

Start with a reproducible symptom

Choose a known test such as ping or TCP from Client PC to Application Server. Save the topology and run the test.

Check the physical/logical layer

Look for a disabled link or interface state Down. A broken link prevents the packet from reaching the next device.

Check IP configuration

Confirm every routed interface has an address and correct prefix. Confirm the client default gateway is in the client subnet.

Check routing

On each router, verify a matching route exists for the destination network and that nextHop is reachable through a connected network.

Check service and firewall

If ping works but TCP/HTTP fails, inspect the destination port, server listening ports, and firewall rules.

Use evidence IDs

Diagnostics cite event IDs. Find those events in the simulation Event timeline. The event tells you where forwarding stopped or which policy rejected traffic.

Repair one variable at a time

Change one setting, save the topology, rerun the same protocol, and compare the result. If the run succeeds, the repair is verified for that test.

Important limitation

The current challenge verifier is intentionally simple and checks for a recent successful run. It does not yet prove that a challenge-specific fault was repaired.
